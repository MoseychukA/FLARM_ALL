# FlyRf_Disp_26_07_19_01

Рабочий исходный проект `FlyRf_Disp_26_05_18_01` адаптирован для RGB-дисплея
`GL050001C0-40` (800×480). Прикладная логика, RS485, EEPROM, кнопка, управление
питанием, Wi-Fi, WEB-настройки и OTA оставлены из исходного проекта. Из
`FlyRf_Disp_26_07_17_19` перенесены только компоновка страниц и шрифты.

## Настройки Arduino IDE

- Плата: **ESP32S3 Dev Module**.
- ESP32 by Espressif Systems: версия 3.x.
- Flash Size: **16 MB** для модуля N16R8.
- PSRAM: **OPI PSRAM**.
- CPU Frequency: **240 MHz**.
- Upload Speed: подходящая для используемого USB/UART-подключения.

В каталоге `libraries` находятся использованные копии `TFT_eSPI` и
`Adafruit_INA219`. При необходимости установите эти библиотеки в Arduino IDE.

## Подключение GL050001C0-40

| Сигнал дисплея | GPIO ESP32-S3 |
|---|---:|
| B3…B7 | 1, 2, 3, 4, 5 |
| G2…G7 | 6, 7, 10, 11, 12, 13 |
| R3…R7 | 14, 15, 16, 17, 18 |
| VSYNC | 19 |
| DE | 45 |
| HSYNC | 47 |
| PCLK | 48 |
| Подсветка/CTRL | 21 |
| DISP | к 3,3 В через 10 кОм |

Другие используемые выводы: RS485 RX/TX/DE — GPIO38/39/40, кнопка — GPIO42,
удержание питания — GPIO41, импульс трекеру — GPIO20, контроль питания —
GPIO46. GPIO46 работает только как вход и не имеет внутренней подтяжки; уровень
должна задавать внешняя схема.

## Стабилизация RGB

- PCLK 24 МГц.
- HSYNC: pulse/back/front = 64/80/42.
- VSYNC: pulse/back/front = 2/74/1.
- Один RGB framebuffer в PSRAM и bounce buffer 60 строк во внутренней RAM.
- Передача изменений начинается после VSYNC.
- Экран обновляется не чаще двух раз в секунду.
- Верхняя строка, таблица, радар и нижняя телеметрия обновляются отдельными
  полосами только при изменении соответствующих данных.
- После HTTP-ответа обновление TFT откладывается на 350–500 мс; во время OTA
  обновления TFT приостановлены.

## WEB-интерфейс

- SSID: `FlyRf_Disp-<номер ESP32-S3>`.
- Пароль: `12345678`.
- Адрес: `http://192.168.1.1/`.
- Wildcard DNS и captive-ответы автоматически вызывают страницу подключения
  на большинстве телефонов и компьютеров.
- Кнопка **Выход** закрывает WEB-вкладку, не выключая точку доступа.

Первый рабочий экран появляется через три секунды после стартовой страницы.

## Архитектура версии 01

`ESP32RF.cpp` остаётся владельцем обработки экранных данных. В нём выполняются:

- обработка одиночного, двойного и длинного нажатия кнопки;
- подтверждение сообщения трекера и временный ручной диапазон радара;
- `displayAllPlanes()` с режимами `INFO_DISPLAY_COORDINATE` и
  `INFO_DISPLAY_MAXI`;
- фильтры скорости и высоты целей, гистерезис, направление изменения высоты;
- расчёт координат, ближайшей цели, автоматического масштаба и уровня тревоги;
- подготовка блоков времени, питания, LoRa, GPS, LAN, SOS и сообщений.

`GL050001C0_40_Display.cpp` не читает `Container`, EEPROM или RS485 напрямую.
Он получает готовую модель кадра из `ESP32RF.cpp` и выполняет только отрисовку
в RGB565 framebuffer и передачу изменившихся областей панели.

Объекты `TFT_eSprite` сохранены в исходной ветви для совместимости, но при
`PROJECT_USE_GL050001C0_40=1` не создаются и не передаются на экран. RGB-панель
использует собственный полноэкранный framebuffer в PSRAM; дополнительный
полноэкранный спрайт увеличил бы расход PSRAM и вероятность срыва RGB DMA.
