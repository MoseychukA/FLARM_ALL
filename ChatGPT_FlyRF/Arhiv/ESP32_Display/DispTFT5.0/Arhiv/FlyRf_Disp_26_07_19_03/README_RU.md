# FlyRf_Disp_26_07_19_03

Полный перенос рабочего проекта `FlyRf_Disp_26_05_18_01` на RGB-дисплей
`GL050001C0-40` 800×480. Из `FlyRf_Disp_26_07_17_19` использована только
компоновка стартовой и рабочей страниц. Прикладная логика, RS485, EEPROM,
кнопка, питание, Wi-Fi, WEB-настройки и OTA сохранены из исходного проекта.

## Главное изменение версии 03

- INA219: 7,00 В соответствует 0%, 12,00 В — 100%.
- Между границами процент рассчитывается линейно: 20% на 1 В.
- Значок аккумулятора содержит пять сегментов по 20%.
- За один цикл разбираются до четырёх накопленных RS485-кадров, после чего
  применяется только уже расшифрованное состояние.

## Порядок обработки данных

1. `RS485Display_loop()` ищет заголовок кадра, проверяет длину, footer и CRC16.
2. Корректный пакет расшифровывается в `ThisAircraft`, `Container[12]` и
   служебное состояние `Remote`.
3. `Traffic_loop()` удаляет устаревшие цели.
4. Wi-Fi и WEB обслуживаются до вывода, чтобы HTTP-пауза могла остановить
   обновление RGB-панели.
5. `Display_loop()` фильтрует принятые параметры и формирует таблицу самолётов
   и координатное поле относительно собственного самолёта.

## Полный перенос графики

Библиотека `TFT_eSPI` полностью удалена из проекта. Нет её заголовков,
`TFT_eSPI`, `TFT_eSprite`, `pushSprite()` и `pushRotated()`.

- `ESP32RF.cpp` обрабатывает `ThisAircraft`, `Container`, фильтры целей,
  тревоги, масштаб, таблицу `displayAllPlanes()`, кнопку и телеметрию.
- `GL050001C0_40_Display.cpp` рисует подготовленное состояние в собственный
  полноэкранный RGB565 framebuffer в PSRAM.
- Этот framebuffer выполняет роль главного спрайта исходного проекта.
- Поле полёта вращается на все 360° математически: азимут цели, курс цели,
  риски и обозначения N/E/S/W вычитают курс собственного самолёта.
- Символ собственного самолёта остаётся неподвижным в центре.
- Верхняя строка, таблица и нижние статусы не вращаются.

Полная перерисовка применяется только при изменении вращающегося поля полёта.
Остальные изменения передаются отдельными горизонтальными областями. Частота
кадров поля ограничена 1 Гц для снижения нагрузки RGB DMA и PSRAM.

## Настройки Arduino IDE

- Плата: **ESP32S3 Dev Module**.
- ESP32 by Espressif Systems: **3.x**.
- Flash Size: **16 MB**.
- PSRAM: **OPI PSRAM**.
- CPU Frequency: **240 MHz**.

Встроена только копия `Adafruit_INA219`. `TFT_eSPI` устанавливать не нужно.

## Подключение GL050001C0-40

| Сигнал дисплея | GPIO ESP32-S3 |
|---|---:|
| B3…B7 | 1, 2, 3, 4, 5 |
| G2…G7 | 6, 7, 10, 11, 12, 13 |
| R3…R7 | 14, 15, 16, 17, 18 |
| VSYNC | 19 |
| DE | 45 |
| HSYNC | 47 |
| PCLK | 48 |
| Подсветка AP3032/CTRL | 21 |
| DISP | к 3,3 В через 10 кОм |

RS485 RX/TX/DE — GPIO38/39/40, кнопка — GPIO42, удержание питания — GPIO41,
импульс трекеру — GPIO20, контроль питания — GPIO46. GPIO46 работает только
как вход и требует внешнего формирования уровня.

## Параметры синхронизации RGB

- PCLK: 24 МГц.
- HSYNC pulse/back/front: 64/80/42.
- VSYNC pulse/back/front: 2/74/1.
- Один framebuffer в PSRAM.
- Bounce buffer: 60 строк во внутренней RAM.
- Передача кадра начинается после VSYNC.
- После HTTP-запроса экран выдерживает паузу 500 мс; во время OTA вывод
  приостанавливается.

## WEB-интерфейс

- SSID: `FlyRf_Disp-<ID ESP32-S3>`.
- Пароль: `12345678`.
- Адрес: `http://192.168.1.1/`.
- Есть кнопки **Применить и остаться** и **Выход**.
- Captive portal автоматически открывает основную страницу на совместимых
  телефонах и компьютерах.

Первый рабочий экран появляется через три секунды после стартовой страницы.
