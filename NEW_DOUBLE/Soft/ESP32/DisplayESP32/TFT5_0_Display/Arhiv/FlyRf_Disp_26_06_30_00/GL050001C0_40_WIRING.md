# GL050001C0-40 for FlyRf_Disp_26_06_30_00

Target module: `ESP32-S3-WROOM-1-N16R8`.

This module provides 16 MB Flash and 8 MB PSRAM. The PSRAM is important for an
800x480 RGB display because the framebuffer should be allocated outside normal
internal RAM.

This project originally uses a 480x480 TFT driven by `TFT_eSPI`.
`GL050001C0-40` is treated here as a 5-inch RGB565 panel, 800x480, driven by
the ESP32-S3 RGB LCD peripheral (`esp_lcd`).

## Pins already used by the project

These pins must not be used by the display:

| Project signal | GPIO |
| --- | --- |
| BOOT | GPIO0 |
| U0TXD | GPIO43 |
| U0RXD | GPIO44 |
| RS485 RX | GPIO38 |
| RS485 TX | GPIO39 |
| RS485 DE | GPIO40 |
| Button 1 | GPIO45 |
| Power hold | GPIO17 |

The current project also uses these pins, so the display mapping avoids them too:

| Project signal | GPIO |
| --- | --- |
| Button 2 / LoRa reset | GPIO7 |
| Trigger / LoRa busy | GPIO18 |
| Power tracker pulse | GPIO20 |
| TFT backlight from old display | GPIO21 |
| LoRa CS | GPIO46 |
| GNSS RX/TX/PPS | GPIO15/GPIO16/GPIO47 |
| SPI MOSI/MISO/SCK | GPIO11/GPIO13/GPIO12 |
| I2C SDA/SCL | GPIO8/GPIO9 |

## Result

The raw RGB GL050001C0-40 cannot be connected to the current FlyRF pinout
without moving something else. The ESP32-S3 RGB peripheral needs 21 unique
signals: `DE`, `VSYNC`, `HSYNC`, `PCLK`, `BL` and `D0..D15`.

After preserving the occupied pins listed above, plus GNSS, SPI, I2C and power
control lines already used by the project, there are not enough unique exposed
GPIOs left for a correct RGB565 bus.

## Practical options

You have two realistic options:

1. Move one of the project peripherals to an I2C/SPI expander or to different
   pins, then give the RGB panel unique GPIO for all 21 signals.
2. Use a GL050001C0-40 carrier with a serial display controller instead of raw
   RGB, so the panel does not require the full RGB bus.

If raw RGB must stay, the least painful candidates to move away from ESP32-S3
GPIO are:

| Move this function | Current GPIO | Suggested replacement approach |
| --- | --- | --- |
| Buttons | GPIO45, GPIO7 | PCF8574/MCP23017 over I2C |
| RS485 DE | GPIO40 | External auto-direction RS485 transceiver or I2C GPIO expander |
| Old TFT backlight | GPIO21 | Reuse as GL050001C0-40 `BL`, because the old TFT is removed |
| LED | GPIO4 | I2C GPIO expander or omit |
| LoRa/SPI CS or reset lines | GPIO46/GPIO7 | Move to expander only if timing is acceptable |

The current `GL050001C0_40_Display.cpp` file is a low-level bring-up module. It
is intentionally disabled until a real, unique RGB pin map is chosen. The old
radar screen in `ESP32RF.cpp` still uses `TFT_eSPI`; a complete radar UI port
requires replacing the sprite and font calls with a new 800x480 RGB drawing
backend.

## Arduino target settings

Use ESP32-S3 with 16 MB Flash and PSRAM enabled. For Arduino CLI this is the
intended board family:

```powershell
arduino-cli compile `
  --fqbn "esp32:esp32:esp32s3:FlashSize=16M,PSRAM=opi" `
  --libraries "FlyRf_Disp_26_06_30_00/libraries" `
  "FlyRf_Disp_26_06_30_00"
```

If your installed ESP32 Arduino core names the PSRAM menu differently, choose
the option that enables the module's 8 MB PSRAM.
