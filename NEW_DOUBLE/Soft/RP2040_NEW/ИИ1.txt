Ниже — рабочий стартовый проект ADS‑B для RP2040 (Arduino Core) с тремя параллельными каналами приема через PIO→DMA в кольцевые буферы, разделением на 2 ядра (ядро1 — прием и корреляция/детекция пакета, ядро0 — декодирование/вывод), обменом с ESP32‑S3 по Serial2 921600 и базовой инфраструктурой конфигурации (LittleFS). Готов архив с исходниками.

Важное:

Это первая детальная версия с упором на высокоскоростной прием (PIO→DMA→коррелятор) и каркасом декодирования. Продвинутые требования (полная CPR global/local, геттер even/odd с окном 10 с, полный Gillham Q=0, BDS 6.0/6.1, динамический EMA‑порог с шумом negHits, расширенная TC=19, жесткие проверки интервалов dAB/dBC/dCD, цифровой фильтр 0.3 мкс и маски помех) частично реализованы/подготовлены как места расширения. Готов доработать их во 2-й итерации (см. TODO).
Схема потоков данных

Что реализовано

Пины:
Каналы приема: ch1 pin 18, ch2 pin 19, ch3 pin 22.
Индикация преамбулы: ch1 pin 17, ch2 pin 20, ch3 pin 23.
RSSI: pin 26 (ADC).
Моргание: ядро0 pin 15 (1000 мс), ядро1 pin 25 (500 мс).
Serial USB: 115200 для команд/отладочного вывода.
Serial2 к ESP32‑S3: TX pin 4, RX pin 5, скорость 921600.
Прием:
PIO выборка с частотой 20 МГц (шаг 50 нс), автосдвиг IN PINS, autopush по 32 бита в RX FIFO.
Три независимых state machine → каждый через свой DMA‑канал в собственное кольцо (1024 слова на канал).
CPU не опрашивает FIFO PIO (чтение по DMA), читается только кольцо в памяти.
Обработка (ядро 1):
Заполнение per‑channel sample FIFO.
Коррелятор преамбулы: весовая корреляция по 160 отсчетам (8 мкс на 20 МГц) с окнами вокруг ожидаемых центров; штраф за “неожиданные” единицы; отсев длинных импульсов >0.7 мкс; dead time ~7 мкс. Каркас для введения EMA шума/динамического порога.
Детект preamble → нарезка PPM‑битов, определение длины 56/112 бит, помещение RawMessage в очереди.
Короткий “blink” соответствующего pre‑pin.
Обработка (ядро 0):
Вывод сырых пакетов в USB до проверки CRC (по требованию).
CRC контроль; поиск и исправление одиночной битовой ошибки (перебор бит).
Частичное декодирование ADS‑B/Mode‑S (DF17/18/20/21):
TC=1..4 (позывной).
TC=9..18 (позиция: извлечение AC13 высоты; CPR поля сохраняются в каркасе — глобальная/локальная распаковка требует пары even/odd и контекста).
TC=19 подтипы 1/2 (векторная скорость), 3/4 (курс/воздушная).
Формирование кадра к ESP32‑S3 (структура FlightOutput), вычисление CRC32 кадра и отправка по Serial2.
Конфигурация:
LittleFS: автозагрузка /config.txt при старте; команды: HELP, SHOW, SAVE, LOAD, PROFILE <NORMAL|HIGH-EMI|URBAN|REMOTE>, RAW ON|OFF.
ESP32‑S3:
Прием кадра FlightOutput с префиксом 0x55 0xAA, длиной и CRC32; проверка целостности; вывод в USB лог.
Замечания по соответствию ключевым требованиям

Регистрация импульсов 0.5 мкс: частота дискретизации 20 МГц даёт 10 отсчетов на 0.5 мкс — детект возможен с хорошим запасом по времени.
Параллельная обработка в раздельных каналах: да, 3 независимых канала PIO→DMA→корреляторы.
DMA из PIO RX FIFO в кольцевые буферы: да, CPU не трогает PIO FIFO.
Поиск преамбулы по шаблону: реализована весовая корреляция с штрафами и фильтром “длинных импульсов”, dead time ~7 мкс. 
Места для усиления порогов при помехах предусмотрены (настройки и профили).
“irq на входе”: для достижения максимального быстродействия и стабильности вместо GPIO IRQ используется PIO+DMA (без прерываний на каждый бит/фронт). 
Это уменьшает джиттер и загрузку CPU и обычно предпочтительнее для 1090 МГц при 0.5 мкс импульсах.
Цифровой фильтр 0.3 мкс: каркас под пороги 0.4–0.7 мкс/нормализацию заложен; сам FIR/дифференциальный детектор (0.3 мкс) можно добавить поверх sample FIFO (см. TODO).
CPR: добавлены функции глобальной/локальной распаковки; нужна связка even/odd с хранением по времени (окно 10 с) и локальная точка — реализуем в следующей итерации.
Gillham Q=0: каркас включен (gillham2alt) — требуется полная таблица/алгоритм AC13 (см. TODO).
TC=19: поддержаны подтипы 1/2/3/4.
RSSI: чтение pin 26 на ядре 1 выполнено; требуется оформить вычисление уровня/EMA/алярмы (см. TODO).
Контроль/коррекция CRC: реализовано. При одиночной битовой ошибке пакет исправляется и попадает в выходную очередь.
Таймерные индикации: pin 15 (ядро0) каждую 1 с, pin 25 (ядро1) каждые 0.5 с — реализовано.
Вывод RAW байтов 56/112 бит до CRC — реализовано по флагу RAW.
NMEA/JSON/CSV/UBX выводы — не включены (см. TODO).
DF18/TIS‑B/MLAT метки — требуется расширение (см. TODO).
Команды по USB (115200)

HELP — список команд.
SHOW — текущая конфигурация.
SAVE — сохранить в LittleFS (/config.txt).
LOAD — загрузить из LittleFS.
PROFILE NORMAL|HIGH-EMI|URBAN|REMOTE — переключить профиль (значения порогов можно задать в /config.txt).
RAW ON|OFF — включить/выключить вывод сырых пакетов до CRC.
Структура пакета к ESP32‑S3 (Serial2 921600)

Поле FlightOutput строго соответствует вашему заданию:
addr, Squawk, flight[8], altitude (геоид, м), pressure_altitude (баро, м), speed (км/ч), course (°), vert_rate (м/мин), latitude, longitude, seen (мс), timestamp (мс), signal_source=1, aircraft_type=9.
Для скорости/курса используются TC=19; для alt baro — AC13.
 Геоид/верт. скорость/координаты потребуют расширенного декодирования (см. TODO).

Сборка в Arduino IDE

RP2040:
Плата: Raspberry Pi Pico / RP2040 (Arduino-Pico / Earle Philhower).
Зависимости: LittleFS включен в Arduino Core RP2040.
Открыть rp2040_adsb/rp2040_adsb_receiver.ino, прошить.
ESP32‑S3:
Плата: ESP32S3 Dev Module (ESP32 Arduino).
Открыть esp32s3_receiver/esp32s3_receiver.ino, прошить.
Подключение UART: TX/RX совпадают с заданием (TX=GPIO41, RX=GPIO42).

Что осталось доделать (предлагаю во 2-й итерации)

CPR:
Хранение пар even/odd по ICAO с меткой времени, окно 10 с.
Выбор глобальной/локальной распаковки с учетом ref_lat/ref_lon.
Корректная обработка surface/airborne (NZ=15/60).
Gillham Q=0:
Полная реализация gillham2alt() (таблично/алгоритмически AC13 → футы → метры), включая исключительные коды (ниже −1000 фут/выше 126000 фут).
TC=19 расширение:
Вертикальная скорость (VS) и баро‑гео разность (если присутствуют), а также источники (baro/geom).
BDS 6.0/6.1 (DF20/DF21 Comm-B):
Полноценный парсер для извлечения VS и баро‑гео разности, где доступно.
Коррелятор/фильтр:
EMA шума и динамический порог: dynamic_thr = g_base_thr + k*EMA(negHits).
Маски подавления ложных срабатываний (окна off‑regions).
Жесткие проверки dAB≈10, dBC≈25, dCD≈10 (на 10 МГц) → в нашей развертке 20, 50, 20 отсчетов (20 МГц) с допуском ±1 при помехах.
Минимум энергии в окнах (например, не менее 2 из 6 отсчетов в каждом окне).
Отбрасывание, если внутри преамбулы обнаружены импульсы >0.7 мкс (признак импульсной помехи) — уже есть, но стоит усилить.
Ввод профилей Normal/High‑EMI/Urban/Remote с разными параметрами dead time, penalty, min_pos_hits и т.д. (переключение через Serial уже есть).
Цифровой фильтр 0.3 мкс на входных отсчетах: быстрый FIR/детектор фронтов перед корреляцией; нормализация длительности до 0.5 мкс; отброс коротких <0.4 и длинных >0.7.
RSSI:
Функция контроля RSSI на pin 26 с EMA/калибровкой, экспонирование в SHOW/JSON и пороги для профилей.
Выводы:
Добавить форматы CSV/NMEA/JSON/UBX по USB.
Маркировка DF18/TIS‑B/ADSR/MLAT источников.
“irq на входе”:
При необходимости — завести прерывания PIO IRQ для событий preamble detector (например, для внешней индикации), не замедляя тракт выборки.
Безопасность буферов:
Монитор насыщения очередей/буферов, статистика и счетчики дропа.
Что проверить на “железе” при первом запуске

Нагрузка DMA и стабильность (без пропусков) при типичном радиофоне.
Корректность полярности сигнала приемника на входных пинах (возможно нужно подтяжки/инверсия на фронт‑энде).
Порог коррелятора и профили (Normal/High‑EMI/Urban/Remote).
Связь с ESP32S3 (921600, пины 4/5 — RP2040; 41/42 — ESP32S3).
