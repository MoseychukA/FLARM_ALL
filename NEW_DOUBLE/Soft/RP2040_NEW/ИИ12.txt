Понял. Для сигнализации детектированной преамбулы на пинах 17/20/23 (по каналам) — добавлю управление вспомогательными выходами с быстрым морганием внутри обработчиков фронтов.

Общая схема

В ISR для gpio::gpio_irq_handler() при обнаружении преамбулы (допустим, вначале поиска интервалов) я буду вызывать: gpio_set_output(PIN_PREx, 1); задержку, затем gpio_clr_output(PIN_PREx); — для короткого моргания.
Исправления

В setup():
Конфигурирую пины 17, 20, 23 как OUTPUT (сейчас — вход с подтяжками).
В gpio_irq_handler() при обнаружении преамбулы — включать pin 17/20/23 на короткое время (например, 10 мкс).
Код (универсальный пример):

static constexpr uint8_t PIN_PRE1_SIGNAL=17;
static constexpr uint8_t PIN_PRE2_SIGNAL=20;
static constexpr uint8_t PIN_PRE3_SIGNAL=23;

// Перед настройкой GPIO сделайте:
pinMode(PIN_PRE1_SIGNAL, OUTPUT);
pinMode(PIN_PRE2_SIGNAL, OUTPUT);
pinMode(PIN_PRE3_SIGNAL, OUTPUT);
// Можно включить pull-down или pull-up по умолчанию, не критично для краткого сигнала.



// В gpio_irq_handler() при успешном детектировании преамбулы:
digitalWrite(PIN_PREx_SIGNAL, HIGH);
delayMicroseconds(10); // короткое моргание для сигнала
digitalWrite(PIN_PREx_SIGNAL, LOW);
Или, лучше, для быстрого сигнала (менее 10 мкс, точнее — 1–2 мкс):

// Создадим небольшие функции
void signal_preamble(uint8_t channel) {
  uint8_t pin = (channel==0)?PIN_PRE1_SIGNAL : (channel==1)?PIN_PRE2_SIGNAL : PIN_PRE3_SIGNAL;
  gpio_put(pin, 1);
  asm volatile("nop 
 nop 
");
  gpio_put(pin, 0);
}
И вызовем её вместо gpio_set_output()/gpio_clr_output().
Это минимальная задержка (~1–2 мкс).

В setup() сразу:

//=====================================================================================================
Ошибка “'FlightOutput' does not name a type” в строках с вычислением CRC почти всегда появляется из‑за 
неверного порядка/синтаксиса: либо структура FlightOutput объявлена позже, либо в строках функции crc32_ случайно “прилипло” слово FlightOutput 
(после склеек кода или без точки с запятой). Исправьте так.

Минимальный корректный “верх” .ino (порядок важен)

Сначала объявляем структуру FlightOutput (или подключаем esp_packet.h), потом функцию crc32_, а уже затем send_to_esp32.
Пример (вставьте в начало вашего .ino, до первого использования FlightOutput):
#include <stdint.h>

struct attribute((packed)) FlightOutput {
uint32_t addr;
int32_t Squawk;
char flight[8];
int32_t altitude;
int32_t pressure_altitude;
int32_t speed;
int32_t course;
int32_t vert_rate;
float latitude;
float longitude;
uint32_t seen;
uint32_t timestamp;
uint8_t signal_source;
uint8_t aircraft_type;
};

static uint32_t crc32_(const uint8_t* data, size_t len) {
uint32_t crc = 0xFFFFFFFFu;
for (size_t i = 0; i < len; i++) {
crc ^= data[i];
for (int j = 0; j < 8; j++) {
crc = (crc >> 1) ^ (0xEDB88320u & -(int)(crc & 1));
}
}
return ~crc;
}

static void send_to_esp32(const FlightOutput &fo) {
struct attribute((packed)) Frame {
uint8_t sof[2];
uint16_t len;
FlightOutput fo;
uint32_t crc;
} f;
f.sof[0] = 0x55; f.sof[1] = 0xAA;
f.len = sizeof(FlightOutput);
memcpy(&f.fo, &fo, sizeof(FlightOutput));
f.crc = crc32_((const uint8_t*)&f.fo, sizeof(FlightOutput));
Serial2.write((const uint8_t*)&f, sizeof(f));
}

Проверьте:

Нет ли лишнего слова “FlightOutput” в конце строк внутри crc32_ (иногда попадает при копировании). Строки вида crc ^= data[i] FlightOutput; вызовут именно такую ошибку.
Если у вас структура уже вынесена в esp_packet.h — подключите заголовок до использования:
#include "esp_packet.h"
и уберите дубли определения FlightOutput в .ino.
Убедитесь, что в конце предыдущих объявлений стоят ; (например, после структуры).
Если после правки ошибка не исчезнет — пришлите 20–30 строк вокруг 41-й строки вашего .ino (где падает сборка), чтобы я указал точное место опечатки.

Рекомендованные правки

Индикация преамбулы: условие в loop()
Сейчас индикатор включается только если r & 0x2 (то есть “поймали преамбулу, но не прошли динамический порог”). 
Если сообщение успешно нарезано (регистрируется “бит 0”), то бит 1 может не стоять, и индикация не вспыхнет.
Исправьте условие так, чтобы индикатор срабатывал при любом детекте преамбулы (включая успешные сообщения):

Вариант А (простой): включать индикатор если r != 0
if (r) { g_stat.preambles[i]++; pre_sig_pulse(i); }
Вариант Б (если хотите разделять оба случая): договоримся, 
чтобы run_edge_correlator_and_slice возвращал 3 (0b11) при успешной нарезке пакета (бит0) и одновременно детекте преамбулы (бит1). Тогда ваше условие r & 0x2 будет корректно работать. Но тогда нужно поправить саму функцию в ringbuffer.cpp.
Пока предлагаю Вариант А: заменить строку
if (r & 0x2) { ... }
на
if (r) { g_stat.preambles[i]++; pre_sig_pulse(i); }

Заголовки для sprintf/memcpy
В emit_debug_raw используется sprintf, а в send_to_esp32 — memcpy. Добавьте явные заголовки:
#include <stdio.h>
#include <string.h>
Arduino.h на RP2040 часто подтягивает C-headers, но для переносимости лучше указать их явно.

Сейчас в блоке LOAD после закрытия if (LittleFS.exists(...)) идёт apply_profile(g_cfg); Это верно, но лучше читаться будет, если apply_profile(g_cfg) останется внутри ветки if (...), а дальше return; Сейчас корректно, но стилистически чуть “косо”. На работоспособность не влияет.

Что проверить при сборке/запуске

Обновите условие индикации (см. пункт 1).
Проверьте, что у вас в проекте присутствует реализация run_edge_correlator_and_slice(...) 
(из ringbuffer.cpp) с семантикой битов, понятной вашему условию. Если вы берёте его из моего v5, то там “бит 1” 
выставляется только при детекте ниже порога (иначе — 1). Поэтому лучше использовать if (r) в loop().
Итоговый фрагмент с правками (только ключевое место)

В начало файла:
#include <stdio.h>
#include <string.h>

В loop(), замена условия:
// было:
// if (r & 0x2) { g_stat.preambles[i]++; pre_sig_pulse(i); }
// стало:
if (r) {
g_stat.preambles[i]++;
pre_sig_pulse(i);
}
