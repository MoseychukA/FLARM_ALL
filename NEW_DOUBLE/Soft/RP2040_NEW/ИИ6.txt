Спасибо за лог. Есть три конкретные проблемы сборки, вот как их исправить.

Конфликт pio_program_t и неправильная инициализация программы PIO
Причина:
В Arduino Core RP2040 тип pio_program_t уже объявлен (в hardware/pio.h), а в вашем adsb_sampler.pio.h он объявлен повторно — конфликт.
Поле instructions в pio_program_t — это указатель на массив инструкций, а у вас туда по ошибке “ложится” литерал, что даёт “invalid conversion from ‘int’ to ‘const uint16_t*’”.
Как исправить (замените полностью содержимое adsb_sampler.pio.h):

Файл: adsb_sampler.pio.h
Содержимое:
#pragma once
#include <hardware/pio.h>
static const uint16_t adsb_sampler_program_instructions[] = {
0x4001 // IN PINS, 1
};

static const pio_program_t adsb_sampler_program = {
.instructions = adsb_sampler_program_instructions,
.length = 1,
.origin = -1
};

static inline void adsb_sampler_program_init(PIO pio, uint sm, int offset, uint pin, uint32_t sample_freq_hz) {
// Настройка входного пина
gpio_init(pin);
gpio_set_dir(pin, GPIO_IN);
gpio_pull_down(pin);

// Конфиг SM
pio_sm_config c = pio_get_default_sm_config();
sm_config_set_in_pins(&c, pin);
sm_config_set_in_shift(&c, true, true, 32);      // shift right, autopush 32
sm_config_set_fifo_join(&c, PIO_FIFO_JOIN_RX);   // RX FIFO объединить

// Частота тактирования под частоту дискретизации
float div = (float)clock_get_hz(clk_sys) / (float)sample_freq_hz;
sm_config_set_clkdiv(&c, div);

// Область wrap — по длине нашей программы (1 инструкция)
sm_config_set_wrap(&c, offset, offset + adsb_sampler_program.length - 1);

pio_sm_init(pio, sm, offset, &c);
pio_sm_set_enabled(pio, sm, true);
}

Важно:

Не объявляем свой typedef pio_program_t — используем тот, что в <hardware/pio.h>.
Обязательно используем отдельный массив adsb_sampler_program_instructions[] и передаём его адрес в .instructions.
DMA: al3_trans_count_trig не существует
Причина:
Вы используете низкоуровневое поле регистра, которого нет в заголовках вашей версии SDK/Arduino Core. Правильнее стартовать DMA вызовом dma_channel_configure(..., start=true) и не трогать dma_hw->ch[...] напрямую.
Как исправить:

В вашей функции setup_pio_dma_channel замените настройку DMA на такую:
channel_config_set_ring(&cfg, true, __builtin_ctz(DMA_RING_WORDS) + 2); // важно +2 из-за 4 байт/слово
dma_channel_configure(
chan,
&cfg,
(void*)c.ring, // dst
(const void*)&pio->rxf[sm],// src
0x7FFFFFFF, // большой счётчик (условно “почти бесконечный”)
true // стартуем сразу
);

И удалите строки с:
dma_hw->ch[chan].al3_write_addr = ...
dma_hw->ch[chan].al3_trans_count_trig = ...

Почему +2 в channel_config_set_ring:

Кольцо у вас на 1024 слова по 4 байта = 4096 байт. Лог2(4096)=12. __builtin_ctz(1024)=10, +2 даёт ровно 12 — правильная обёртка по байтам.
Мелочи, которые стоит проверить
pio_add_program вызывайте с &adsb_sampler_program:
int off = pio_add_program(pio, &adsb_sampler_program);
В adsb_sampler_program_init для wrap нужно offset и offset + length - 1 (см. код выше).
Заголовок regs dreq подключён: #include <hardware/regs/dreq.h> — корректно.
Если 0x7FFFFFFF в счётчике DMA кажется избыточным — можно поставить, например, 0x1000000. Система будет работать, пока счётчик не “выгорит” (это долгие часы); при желании можно добавить перезапуск по прерыванию, но для прототипа обычно хватает большого значения.
Итого “патч” по файлам

adsb_sampler.pio.h — заменить на приведённый выше вариант (устранит обе ошибки с pio_program_t и инициализацией инструкций).
В вашей .ino (функция setup_pio_dma_channel):
сменить ring size на __builtin_ctz(DMA_RING_WORDS)+2
запуск DMA через dma_channel_configure(..., start=true)
удалить прямые обращения к dma_hw->ch[].al3_*
