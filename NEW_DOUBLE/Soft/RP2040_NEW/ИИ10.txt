Понял, почему «останавливает» — вы попали в шторм прерываний от PIO:
 при 20 МГц и autopush каждое 32‑битное слово state machine кладёт в RX FIFO с частотой ≈ 625 кГц на канал. IRQ “RX FIFO not empty” дергается постоянно, ядро уходит в обработчик и всё «замирает».

Вы просили вариант без DMA с прерываниями на пинах 17, 19, 22. Правильное решение — полностью уйти от PIO и читать фронты через GPIO‑IRQ, собирая временные метки, а затем детектировать преамбулу/битовую последовательность по временам.

Что поменять (кратко)

Убрать PIO и его IRQ (весь код с pio_add_program, pio_set_irq0_source_enabled, irq_set_exclusive_handler и т.п. — удалить).
Настроить три GPIO на вход: 17, 19, 22.
Включить прерывания по изменению уровня (восходящий/нисходящий фронт) для каждого из этих пинов.
В обработчике IRQ только писать метки времени (time_us_32()) и уровень (rise/fall) в кольцевой буфер Канала (минимум кода в ISR!).
На втором ядре или в loop() разбирать буферы: искать преамбулу по интервалам, затем декодировать PPM биты по центрам полубитов.
Минимальные правки (эскиз)

Настройка GPIO IRQ
В setup():
Настроить входы: gpio_init(pin); gpio_set_dir(pin, GPIO_IN); gpio_pull_down(pin) или gpio_pull_up(pin) — по полярности вашего приёмника.
Подключить один общий колбэк на GPIO IRQ и включить его для каждого пина.
Пример:

В начале .ino добавьте структуру буфера для фронтов:
struct Edge { uint32_t t; uint8_t level; };
static volatile Edge edges[3][4096];
static volatile uint16_t widx[3] = {0}, ridx[3] = {0};

Инициализация:
gpio_init(17); gpio_set_dir(17, GPIO_IN); gpio_pull_down(17);
gpio_init(19); gpio_set_dir(19, GPIO_IN); gpio_pull_down(19);
gpio_init(22); gpio_set_dir(22, GPIO_IN); gpio_pull_down(22);

gpio_set_irq_enabled_with_callback(17, GPIO_IRQ_EDGE_RISE | GPIO_IRQ_EDGE_FALL, true, &gpio_irq_handler);
gpio_set_irq_enabled(19, GPIO_IRQ_EDGE_RISE | GPIO_IRQ_EDGE_FALL, true);
gpio_set_irq_enabled(22, GPIO_IRQ_EDGE_RISE | GPIO_IRQ_EDGE_FALL, true);

Обработчик:
void gpio_irq_handler(uint gpio, uint32_t events) {
uint8_t ch = (gpio==17)?0 : (gpio==19)?1 : (gpio==22)?2 : 255;
if (ch>2) return;
uint32_t t = time_us_32();
uint8_t lvl = (events & GPIO_IRQ_EDGE_RISE) ? 1 : 0;
uint16_t wi = widx[ch];
edges[ch][wi] = { t, lvl };
widx[ch] = (wi + 1) & 0x0FFF; // 4096
}

Обработка фронтов и детекция преамбулы
На core1 или в loop() забираете фронты из кольца (по ridx[ch]), восстанавливаете длительности импульсов и пауз, ища последовательность преамбулы:

Ожидаемые центры пиков (в мкс от t0): 0, 0.5, 1.0, 3.5, 4.0, 5.5.
Проверить интервалы между центрами: dAB≈0.5, dBC≈0.5, dCD≈2.5, dDE≈0.5, dEF≈1.5 мкс (допуск ужимается при помехах).
Отброс, если встречаются «длинные» импульсы >0.7 мкс.
Dead time 6–8 мкс после срабатывания.
После t0+8 мкс (после преамбулы) декодируете 56/112 бит:

Для каждого бита n: окно [t0+8+n1.0, t0+8+n1.0+1.0] мкс.
Считайте, где находится импульс: в первой половине (бит=1) или во второй (бит=0). Это можно делать по ближайшим фронтам/ширине импульса.
Вывод и остальное — без изменений
USB 115200, Serial2 921600, CRC/правка 1 бита, сборка FlightOutput — всё остаётся.
Почему так не «стопорит»

GPIO‑IRQ приходят только при фронтах, а не непрерывно, как PIO с частотой семплирования. Нагрузка небольшая: каждый пакет ADS‑B даёт ограниченное число фронтов.
Что с текущим “irq_nodma” архивом

В нём как раз использовались IRQ PIO (PIO0_IRQ_0/PIO1_IRQ_0), которые и «повесили» систему из‑за непрерывного заполнения FIFO на 20 МГц. Их нужно заменить на GPIO‑IRQ, как описано выше.
