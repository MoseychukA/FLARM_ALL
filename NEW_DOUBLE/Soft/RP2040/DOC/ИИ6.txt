Да, пороги корреляторa можно “ужесточить” и/или сделать адаптивными. Ниже два варианта: простой (статически повышаем пороги) и адаптивный (порог подстраивается под уровень помех). Оба совместимы с текущей функцией corr_preamble_and_get_t0().

Вариант A — простой (усиленные пороги)

Повышаем минимальный балл корреляции.
Уменьшаем допустимое число “неожиданных” единиц в зонах, где ожидается ноль (penalty).
Требуем минимальное число попаданий в “ожидаемые” окна преамбулы и минимальное отношение “полезных” к “помеховым”.
Добавьте вверху файла adsb_rp2040_adsb.ino (рядом с константами таймингов) набор тюнингов:

PRE_POS_W, PRE_NEG_W — веса для совпадений/несовпадений.
PRE_SCORE_THR — минимальный суммарный балл.
PRE_PENALTY_THR — максимально допустимых “неожиданных” единиц.
PRE_MIN_POS_HITS — минимум попаданий в ожидаемые окна.
PRE_MIN_RATIO — минимальное отношение posHits/(negHits+1).
Пример жестких настроек для сильных помех:

PRE_SCORE_THR 36…48
PRE_PENALTY_THR 3…4
PRE_MIN_POS_HITS 18
PRE_MIN_RATIO 3.0
Замените тело corr_preamble_and_get_t0() на это (подставьте ваши значения тюнинга):

#define PRE_POS_W         3
#define PRE_NEG_W        -1
#define PRE_SCORE_THR    40   // раньше было ~20
#define PRE_PENALTY_THR   3   // раньше было 6
#define PRE_MIN_POS_HITS 18
#define PRE_MIN_RATIO   3.0f

static bool corr_preamble_and_get_t0(const PreambleState &ps, uint32_t cur_pos, uint32_t &t0){
  // извлечь последние 80 семплов из сдвиговых регистров (как было)
  uint8_t bits[80];
  for (int i=0;i<80;i++){
    int idx = 127 - i; int w = idx>>5; int b = 31 - (idx & 31);
    bits[79-i] = (ps.shift[w]>>b) & 1;
  }

  // ожидаемые окна 0.5 мкс около ~5, 15, 40, 50 отсчетов
  int score=0, penalty=0, posHits=0, negHits=0;
  for (int i=0;i<80;i++){
    bool expect = ( (i>=2 && i<=7) || (i>=12 && i<=17) || (i>=37 && i<=42) || (i>=47 && i<=52) );
    if (bits[i]) {
      if (expect) { score += PRE_POS_W; posHits++; }
      else        { score += PRE_NEG_W; negHits++; penalty++; }
    }
  }

  // дополнительные критерии
  float ratio = (float)posHits / (float)(negHits + 1);
  if (score >= PRE_SCORE_THR &&
      penalty <= PRE_PENALTY_THR &&
      posHits >= PRE_MIN_POS_HITS &&
      ratio >= PRE_MIN_RATIO)
  {
    t0 = cur_pos - 80;
    return true;
  }
  return false;
}
Вариант B — адаптивный (подстройка к помехам)

Ведём скользящую оценку “фонового шума” (сколько неожиданных единиц встречается, когда преамбула не детектировалась).
Порог PRE_SCORE_THR делаем динамическим: base + k*sqrt(var) или сдвиг в зависимости от среднего negHits.
Простой и дешёвый по вычислениям вариант: увеличивать порог на α*negHitsAvg.
Добавьте глобальные переменные/структуру:

static float g_neg_avg = 0.0f;    // экспоненциальное среднее по negHits
static float g_neg_alpha = 0.02f; // константа EMA (подберите)
static int   g_base_thr = 36;     // базовый порог
static float g_k = 1.5f;          // коэффициент "жесткости" к шуму
И измените принятие решения:

int dynamic_thr = g_base_thr + (int)(g_k * g_neg_avg);

// ... вычисление score, penalty, posHits, negHits как выше ...

bool ok = (score >= dynamic_thr) &&
          (penalty <= PRE_PENALTY_THR) &&
          (posHits >= PRE_MIN_POS_HITS);

// Обновляем фон (если не сработала детекция — считаем это фоном)
if (!ok) {
  g_neg_avg = (1.0f - g_neg_alpha)*g_neg_avg + g_neg_alpha*(float)negHits;
}

if (ok) {
  t0 = cur_pos - 80;
  return true;
}
return false;
Дополнительные приёмы повышения устойчивости

Мёртвое время после срабатывания (dead time 6–8 мкс), чтобы не детектировать повторно хвост того же пакета.
Проверка интервалов между центрами пиков (в событиях pulse_times): dAB≈10, dBC≈25, dCD≈10 с более узким допуском (±1) при сильных помехах.
Минимум энергии в ожидаемых окнах: posHits для каждого окна (например, не менее 2 из 6 отсчётов).
Отбрасывание детекций, если в пределах преамбулы обнаружены “длинные” импульсы >0.7 мкс (признак импульсной помехи).
Рекомендации по настройке

Начните с PRE_SCORE_THR=40, PRE_PENALTY_THR=3, PRE_MIN_POS_HITS=18, PRE_MIN_RATIO=3.0.
Если продолжаются ложные срабатывания — увеличивайте PRE_SCORE_THR шагами по 4 и/или снижайте PRE_PENALTY_THR до 2.
Если начинаете терять реальные пакеты — немного ослабьте PRE_SCORE_THR и/или увеличьте PRE_PENALTY_THR на 1.
